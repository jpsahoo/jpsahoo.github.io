Q12. Build a Four-Thread Program10 pts

Write a small program in C/C++, Java, or Python that creates four threads. The goal is not to build a large application. The goal is to see how multiple threads can execute within the same process.

Each thread should:

  • Its thread number / identifier.
  • A start message.
  • The result of a small computation.
  • An end message.

Recommended Python starting point:

import threading
import time

def worker(n):
    print(f"Thread {n} started")
    total = sum(i * i for i in range(100000))
    time.sleep(0.2)
    print(f"Thread {n} result = {total}")
    print(f"Thread {n} finished")

threads = []

for i in range(4):
    t = threading.Thread(target=worker, args=(i+1,))
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print("All threads completed.")

Run your program at least three times. Compare the output rather than assuming that the order will always be the same.

After observing all three runs, answer:

  1. Did the output order remain identical?
  2. Why can thread execution order change?
  3. Which resources are shared by threads in the same process?
  4. Which state is specific to an individual thread?
Submit: Source code + output from three executions + one screenshot of the terminal.
Q13. Thread Mapping Models6 pts

The textbook describes three ways that user-level threads can be mapped to kernel threads. Draw and explain the following three models. Focus on understanding the mapping rather than memorizing the diagrams.

Many-to-One T1 ─┐ T2 ─┼────→ K1 T3 ─┤ T4 ─┘
One-to-One T1 ─────→ K1 T2 ─────→ K2 T3 ─────→ K3 T4 ─────→ K4
Many-to-Many T1 ─┐ T2 ─┼────→ K1 T3 ─┤ ↘ K2 T4 ─┘ ↘ K3

For each model, explain in your own words:

  • How user-level threads map to kernel threads.
  • One advantage.
  • One limitation.
Submit: Your three diagrams and a comparison table.
