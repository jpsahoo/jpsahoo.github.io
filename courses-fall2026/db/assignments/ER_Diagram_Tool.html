What is "ER description code"? (and what does DSL mean?)

In this tool you do not drag and drop shapes. You type one short line for each item in your diagram. For example, the line entity Student tells the tool to draw a rectangle named Student. When you click Compile, the tool draws the whole diagram from your lines.

These lines are written in a small text language. A language built for one specific job is called a DSL, which stands for Domain-Specific Language. "Domain" means the subject area (here, ER diagrams) and "specific" means the language only does that one job. SQL is another example: it is a DSL for working with databases. On this page we simply call it ER description code. Every line you can write is listed in section 4, and section 3 shows the symbol each line produces.

Naming rule: entity/relationship/attribute names must be a single word — no spaces (use underscores, e.g. Date_of_Birth). Every name you invent in entity/weak entity/relationship lines must be spelled identically everywhere else you reference it.

One notation simplification: the textbook draws a weak entity's partial key with a dashed underline (to distinguish it from a full key). This tool only has one "key" style (PK, solid underline) — mark a weak entity's partial key with PK too and note in your answer that it is a partial key, not a full key.
