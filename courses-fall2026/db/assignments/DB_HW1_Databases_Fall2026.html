Chapter 3 · Data Modeling Using the ER Model 📖 Sec 3.3–3.10

~2 hours 50 points

Chapter Objective

Model a small university database using ER concepts, then build the full diagram using the ER Diagram Tool.

Scenario for Q9–Q14: the "Taiwan Tech University" database

Taiwan Tech (National Taiwan University of Science and Technology) needs a database to track student enrollment and grades, adapted from the University example in Sec 3.10:

  • The university is organized into colleges (COLLEGE). Each college has a unique name, a main office, a phone number, and a faculty member who is dean.
  • Each college administers several departments (DEPARTMENT). Each department has a unique name, a unique code, an office, a phone number, and a faculty member who chairs it (with the date the chair started).
  • A department offers a number of courses (COURSE). Each course has a unique title, a unique course code, credit hours, a level (Undergraduate/Graduate), and a description.
  • The database tracks instructors (INSTRUCTOR): a unique ID, name, office, one or more contact phone numbers, and academic rank. Each instructor works for one primary department.
  • The database tracks students (STUDENT): a unique student ID, name (first, middle, last), address, phone, a major department, and date of birth.
  • Courses are offered as sections (SECTION). Each section has a section number, semester, year, classroom, and meeting days/time; each section belongs to exactly one course and is taught by exactly one instructor.
  • Students enroll in sections and receive a grade for each — a many-to-many relationship between STUDENT and SECTION.

Q13. Build the Taiwan Tech University ER Diagram — Main Task20 pts
What is "ER description code"? (and what does DSL mean?)
The ER Diagram Tool does not ask you to drag and drop shapes. Instead, you type one short line for each item in your diagram. For example, the line entity Student tells the tool to draw a rectangle named Student. Then you click Compile and the tool draws the diagram from your lines.
These lines are written in a small text language. Computer scientists call a language built for one specific job a DSL, which stands for Domain-Specific Language. "Domain" means the subject area (here, ER diagrams), and "specific" means the language can only do that one job. SQL is another example: it is a DSL for working with databases. In this homework we simply call it ER description code. You do not need any other programming knowledge: each line follows one of the patterns listed on the tool page.

Open the ER Diagram Tool (it opens as a new page with a starter example already loaded). In the tool, you describe your diagram in a few lines of text (the ER description code), and the tool draws the complete Chen-notation ER diagram for you. Build the diagram for the Taiwan Tech University database described above. Your diagram must include:

  • All 6 entity types, with SECTION marked as a weak entity
  • Correct key attribute(s) (marked PK) for every entity that has one
  • The composite Name attribute for Student
  • At least one multivalued attribute (e.g. Instructor's phone numbers)
  • At least one derived attribute (e.g. Student's Age, derived from Date of Birth)
  • All relationships from Q11 (at least 4), each with a cardinality ratio and total/partial participation
  • The identifying relationship connecting Section to its owner entity, drawn with a double-outline diamond
How to use the tool: type or paste your ER description code into the editor, click Compile to draw the diagram, then use the Download SVG / PNG / JPG / PDF buttons to save it. Every line type you can write is listed, with a picture of its symbol, on the tool page itself.
Full credit (itemized, 20 pts total): 2 pts × 6 correctly modeled entities (12 pts) + 2 pts composite attribute + 2 pts multivalued attribute + 2 pts derived attribute + 2 pts for ≥4 correctly labeled relationships with cardinalities. A careful, engaged student who follows the checklist above should comfortably earn 16–20/20.
Submit: Your exported diagram image (SVG or PNG) and the ER description code you typed, both pasted into the template. Your grader needs the code to check exactly what you modeled.
